# 全书大纲与章节规格（Outline）

书名：**《智能体运行时原理 —— 从 LangChain 到 LangGraph，及可迁移的 Agent 设计法则》**

全书 5 部分、23 章 + 2 附录，约 10 万字。核心立场：**LangChain / LangGraph 只是某一时刻的一组实现，真正通用的是它们背后的运行时原理。**

---

## 第一部分　问题空间：框架为什么必然出现

### 第 1 章　从「调用模型」到「编排智能体」　`01-from-api-to-agent.md`
主旨：框架不是被发明出来的，是被问题逼出来的。
- 三个阶段的抽象跃迁：单次调用 → 会话式交互 → 有状态可循环的智能体
- 朴素实现的失败清单：无记忆、无工具、无重试、无终止条件、不可恢复
- 一次典型事故的解剖：为什么"只是加个循环"会失控
- 抽象税：框架给了什么，又拿走了什么
- 判据：什么时候**不该**用框架

### 第 2 章　LLM 应用的第一性原理　`02-first-principles.md`
主旨：所有架构决定都能回溯到 LLM 的四个物理约束。
- 约束一：Token 与上下文窗口——系统里唯一的"内存"
- 约束二：无状态——每次调用都是重新开始
- 约束三：概率性——同样的输入不保证同样的输出
- 约束四：副作用不可逆与延迟不可忽略（成本三要素：token/时间/金额）
- 四约束如何推导出"外部状态 + 显式控制流 + 校验层 + 可观测性"的必要性
- 与 Web 服务的关键差异对照表

### 第 3 章　框架抽象的本质：把什么变成接口　`03-what-abstractions-do.md`
主旨：好抽象的三个判据——可组合、可替换、可观测。
- 抽象在做的事：把"变化的实现"和"稳定的契约"分开
- 契约先于实现：为什么一切都要 Schema 化
- 控制反转：框架接管了执行循环，你交出了什么
- 抽象泄漏：LangChain 历史上被推翻的几类抽象（以及原因）
- 抽象三判据的自检清单

### 第 4 章　LangChain 家族的全景与演进脉络　`04-family-and-evolution.md`
主旨：读不懂这套生态，多半是因为不了解它的版本史。
- 三代抽象：Chain（硬编码流水线）→ LCEL（声明式组合）→ Graph（显式状态机）
- 职责边界：LangChain（组件与协议）/ LangGraph（运行时）/ LangSmith（观测）/ LangServe（服务化）
- 为什么核心能力从 LangChain 迁移到了 LangGraph
- 生态分层图与"依赖族"地图（Pydantic、模型适配层、检索栈、协议层）
- 学习路径建议：先原理后 API

## 第二部分　LangChain 的抽象原理

### 第 5 章　Runnable 协议：统一执行语义　`05-runnable-protocol.md`
主旨：一切组件实现同一个接口，才可能自由组合。
- 问题：N 个组件、M 种调用方式 → 适配爆炸
- 统一协议的四要素：输入输出契约、四种执行模式（单次/批量/流式/异步流式）、配置注入、生命周期回调
- 四种模式的语义差异与为什么要四种都有
- 同步与异步双轨制：必要性、代价、常见踩坑
- 回调机制：可观测性的埋点位置

### 第 6 章　LCEL：声明式编排的原理　`06-lcel-principles.md`
主旨：管道符背后是组合子代数，不是语法糖。
- 声明式 vs 命令式：描述"是什么"而非"怎么做"
- 组合子全集：顺序、并行、分支、透传、动态路由
- 流式传播（streaming propagation）原理：为什么能端到端流式输出
- 失败语义：回退、重试、超时的组合规则
- 表达力边界：LCEL 表达不了什么，以及为什么必须转向图

### 第 7 章　模型与消息：LLM 适配层的原理　`07-model-adaptation.md`
主旨：适配层要抹平的不是 API 差异，而是能力差异。
- 消息角色模型：System / Human / AI / Tool 四角色的语义与约束
- 统一 provider 抽象必须处理的差异：多模态、工具调用格式、流式分片、停止条件、token 计费
- 工具调用协议的本质：模型输出结构化意图 → 宿主执行 → 结果回灌
- 结构化输出的三条技术路线：提示约束、函数调用、受限解码（各自的可靠性）
- 能力降级策略：模型不支持某能力时怎么办

### 第 8 章　提示与解析：IO 边界的类型契约　`08-prompt-and-parsing.md`
主旨：提示模板是函数，解析器是契约的守门人。
- 提示模板的本质：模板 + 变量绑定 = 从数据到消息的纯函数
- 动态提示：示例选择器、上下文注入、条件片段
- 输出解析器的三层职责：抽取 → 校验 → 修复/重试
- 容错设计模式：宽松解析、修复循环、降级输出、失败升级
- 契约的边界：什么时候该放弃解析、改用工具调用

### 第 9 章　检索增强（RAG）的原理　`09-rag-principles.md`
主旨：RAG 是"外挂记忆"，不是"更大模型"；它的失效点几乎全在检索而非生成。
- 为什么需要 RAG：知识时效性、私有性、可溯源性、成本
- 检索栈四层：切分 → 嵌入 → 索引/召回 → 重排
- 失效模式图谱：相似≠相关、切分切断语义、多跳问题、跨模态
- 上下文装配策略：数量、顺序、去重、引用标注、预算分配
- 进阶方向：混合检索、查询改写、结构化/图检索的动机
- 评估 RAG 的正确姿势：召回率与忠实度分开测

## 第三部分　LangGraph：从链到图

### 第 10 章　为什么链不够：Agent 循环的本质　`10-why-graphs.md`
主旨：循环 + 状态 + 终止条件 = 智能体；DAG 表达不了这三者。
- DAG 的三重天花板：不可回边、次数固定、无法表达"再想想"
- Agent 循环的最小模型：观察 → 决策 → 行动 → 观察
- 用无环图模拟循环的代价（递归、状态丢失、无法暂停）
- 图作为通用计算模型的合理性
- 什么场景仍然是链的天下（别为了图而图）

### 第 11 章　状态与通道：图的数据模型　`11-state-and-channels.md`
主旨：State 是图中唯一的真相来源，Reducer 决定并发安全。
- 共享状态 vs 消息传递两种范式
- 状态的读写规则：节点读全量、写增量
- 归约器（Reducer）语义：覆盖、追加、求和、去重、自定义合并
- 通道（Channel）与超步（super-step）：值如何在节点间流转
- 状态设计三原则：可序列化、可合并、可解释
- 反模式：把状态当全局变量用、状态膨胀、状态里放不可序列化对象

### 第 12 章　执行引擎：超步模型与调度　`12-execution-engine.md`
主旨：并行节点 + 同步边界，是可复现性的来源。
- 超步（BSP）执行模型：节点并行计算 → 边界同步 → 状态合并 → 下一超步
- 调度决策：谁是下一个节点、条件边的求值时机
- 确定性从何而来：为什么同一个检查点重放结果一致
- 与工作流引擎的对比（Airflow / Temporal / 数据流）：相似与根本差异
- 并发控制的现实约束：速率限制、共享资源、幂等性要求

### 第 13 章　持久化与检查点：Agent 能力的地基　`13-persistence-and-checkpoints.md`
主旨：不可恢复是 Agent 的原罪，检查点把它治好了。
- 检查点保存什么：状态快照 + 待执行任务 + 版本信息
- 线程（Thread）与会话标识：多会话隔离的机制
- 时间旅行：回到任意历史检查点重放/分叉
- 持久化后端选型：内存、SQLite、Postgres 的能力矩阵
- 幂等性与副作用管理：重放时如何避免重复扣款/重复发消息
- "可恢复"带来的架构自由度（长任务、断点续跑、灰度调试）

### 第 14 章　中断与人在回路　`14-interrupts-and-hitl.md`
主旨：中断不是暂停线程，而是一次"有契约的退出与重入"。
- 硬中断与软中断：区别与适用场景
- 三种人在回路模式：审批（approve）、编辑（edit）、工具确认（confirm）
- 中断状态的构造与恢复契约：如何保证恢复时上下文完整
- 一致性挑战：中断期间外部世界在变化
- 长时中断的工程问题：超时、过期、并发恢复、权限校验

### 第 15 章　多智能体拓扑　`15-multi-agent-topologies.md`
主旨：多智能体是组织设计问题，不是技术升级。
- 三种拓扑：主管（Supervisor）、群体（Swarm）、层级（Hierarchical）
- 子图与命名空间：状态隔离与作用域
- 通信的代价：上下文膨胀、信息丢失、延迟累积
- 死循环与失控的护栏：预算、跳数、单调性检查
- 何时**不该**用多智能体：单智能体的能力上限往往被高估

## 第四部分　依赖族与生态

### 第 16 章　Schema 契约与 Pydantic 的角色　`16-schema-contracts.md`
主旨：Schema 是 Agent 系统里唯一能挡住不确定性的墙。
- 三处 Schema：模型输出、工具参数、图状态
- 校验即防线：把不确定性挡在系统边界之外
- 类型到提示的映射：Schema 如何变成模型的约束
- 校验失败的处理分支：重试、修复、降级、上报
- 反面案例：Schema 过严导致模型永远无法满足、过松导致下游崩溃

### 第 17 章　协议层：工具与智能体的标准化　`17-protocols-mcp.md`
主旨：协议化把 M×N 集成问题变成 M+N。
- 集成的组合爆炸：模型 × 工具 × 宿主
- 工具标准化的核心抽象：描述、参数 Schema、结果结构、错误语义
- MCP 的能力模型：工具、资源、提示模板三类原语；客户端-服务器角色
- 传输与生命周期：本地进程、远程连接、能力协商
- Agent 间协议（A2A 等）的设计分歧：任务导向 vs 对话导向
- 协议化的代价：抽象损耗、版本兼容、安全边界（权限与注入风险）

### 第 18 章　可观测性与评估　`18-observability-and-eval.md`
主旨：看不见的执行轨迹，等于不可维护的系统。
- Trace 与 Span：把执行树变成可分析的数据结构
- 关键埋点：每次模型调用的输入输出、token 与耗时、工具调用与结果、状态变更
- 复现难题：概率性系统的可复现性策略（种子、快照、重放）
- 评估的三个层次：单步（组件级）、轨迹（过程级）、端到端（结果级）
- LLM-as-Judge 的原理、偏差与校准方法
- 回归闭环：数据集、基线、线上反馈回流

### 第 19 章　部署与运行时形态　`19-deployment.md`
主旨：Agent 的部署约束和普通 Web 服务不一样。
- 为什么长任务、可中断、可恢复决定了部署架构
- 三种形态：进程内库、独立服务、托管运行时（能力与代价对比）
- 队列、唤醒与超时：长时中断的调度需求
- 成本与限流：token 预算、并发上限、降级策略
- 灰度与回滚：提示和模型变更如何安全上线

## 第五部分　原理迁移：超越具体框架

### 第 20 章　Agent Loop 的通用模式　`20-agent-loop-patterns.md`
主旨：所有 Agent 都是"循环 + 决策"，差别只在决策函数。
- 模式一：ReAct——思考与行动的交替
- 模式二：Plan-Execute——先规划后执行，可并行
- 模式三：Reflexion——自我批判与重试
- 模式四：Router / Dispatcher——分类后分发
- 循环控制四要素：终止判据、预算、进展检测、护栏
- 从"提示工程"到"控制流工程"的范式转变

### 第 21 章　上下文工程　`21-context-engineering.md`
主旨：上下文是 Agent 最稀缺的资源，编排它比堆砌它更重要。
- 上下文预算：系统提示、历史、检索结果、工具输出、中间推理的分配
- 压缩策略：摘要、截断、结构化提取、卸载到工具/文件系统
- 记忆分层：工作记忆、情景记忆、语义记忆、程序性记忆
- 何时该"忘记"：过期、冲突、低价值信息的清理策略
- 长任务的上下文管理：子目标、检查点、外部化便签

### 第 22 章　如果你从零设计一个 Harness　`22-design-your-own-harness.md`
主旨：把全书原理压成一份设计清单和决策矩阵。
- 五个必答设计题：状态放哪、控制流谁定、怎么持久化、工具怎么接、怎么观测
- 设计清单（分模块，每项含"不做的后果"）
- 决策矩阵：自研 vs 用框架，各维度权衡
- 主流方案定位对比：LangGraph / AutoGen / CrewAI / 纯自研
- 演进路线：从最小可用到生产级的分阶段建议
- 三个最容易踩的架构陷阱

### 第 23 章　结语：框架会变，原理不会　`23-conclusion.md`
主旨：把注意力放在不变量上。
- 本书的原理清单（不变量收敛版）
- 框架生命周期规律：抽象会被推翻，约束不会
- 如何持续跟踪新框架而不被裹挟
- 给读者的行动建议
